### 回答と根拠の変化

**Q1：根拠を維持して入力が減った。** 4実行とも、元の重みを固定し低ランクの小さな追加行列を学習するLoRAと、元の重みの4bit化を加えるQLoRAを説明した。第2回p.51/52を根拠として引用し、内容と整合した。検索3件でもp.51/52を取得でき、検索は各1回のまま。平均入力は3032→2077 tokensとなった。品質が改善したという結果ではなく、今回の質問では主要な根拠を維持したまま入力を減らせた例である。

**Q2：検索を減らしても入力は増えた。** 検索5件では各1回で第3回p.39（コンパクションと外部メモリ）とp.40（長期メモリへの選別）を取得した。検索3件では最初にp.65/39/38を取得し、p.40が入らなかった。両回とも「日々のメモ／長期メモリ」を追加検索してp.40を取得し、回答した。4実行とも、同じセッションでの履歴要約とセッションをまたぐ保存・読み戻しを区別し、日々のメモを全件長期保存するわけではないと説明できた。一方、検索回数は1→2回、モデル応答は2→3回となり、平均入力は2499.5→4490.5 tokens、平均推定費用も増えた。追加のモデル応答ではそれまでの会話・ツール結果も入力に含まれるため、1回の検索件数だけでは合計負担を判断できない。

**Q3：数値は創作しなかったが、確認範囲の表現には課題が残る。** 4実行とも今回作ったRAGの実測平均応答時間・正答率を回答せず、手元の実験ログ等が必要とした。第2回p.13の反復評価の説明を引用している。検索3件では平均入力が3207→2115 tokensに減った。ただし「第1〜3回の講義資料を確認した」という表現は、実際には上位3件または5件を検索した範囲を広く見せる。数値の捏造を避けられたことと、資料全体に情報がないと網羅的に証明できたことは区別する必要がある。

### 気づき・疑問・制約

検索件数を減らすことと、回答全体の入力や費用を減らすことは同じではなかった。単一話題のQ1には3件で足りたが、複数論点のQ2には追加検索が必要だった。今回の用途には一律3件より、複数論点を含む質問では5件を基本にする判断が妥当と考える。ただし、今回は教材を理解するための少数例であり、最適な件数を確定したわけではない。

時間は3件条件でもQ1が16.51〜25.10秒、Q2が17.78〜26.79秒、Q3が7.12〜25.22秒と変動した。各条件2回だけで、実行順もランダム化していない。モデルが作る検索語・回答長・サービス混雑も変わるため、速度や費用の一般的優劣、統計的有意差、未見質問への正答率を主張しない。今回の3問を見て設定を再調整してはいない。

変更前Q1の2回目は初回試行が503で失敗したため、同条件で再試行した。成功12件とは別に [失敗ログ](results/failures/k5_q1_r2_attempt1_503.txt) を残した。失敗試行はusageが得られず、表の時間・費用には含めていない。したがって表は作業全体の待ち時間・総費用ではない。成功12件の全原文JSON/TXTと [summary.csv](results/summary.csv) を保存した。

### 再現・検証とAI利用

`run_capture.py q1 1` は実際のAPIを呼び、既存の同名JSONがあれば上書きを拒否する。再実行する場合は、まずこの提出内容を含むリポジトリの別コピーを作る。そのコピー内で既存の `lectures/05/results` を未使用の名前（例：`results_saved`）へ移し、空の `lectures/05/results` を作る。`app/config.py` の `RAG_TOP_K` を5にし、q1→q2→q3の順でそれぞれ `run_capture.py q1 1`、`run_capture.py q1 2` と同様に実行する。次に設定を3へ変え、同じ6実行を行う。今回の原本ログは変更しない。GEMINI_API_KEYは環境変数へ設定し、キーをコードやログに書かない。

```bash
# 既存ログの検算（API不要）
uv run --frozen --python 3.12 python lectures/05/verify_results.py
uv run --frozen --python 3.12 pytest -q
git diff --check
```

12件の原メッセージから入出力tokens・モデル応答数・ツール数・最終回答を照合し、モデル/質問/資料/コードのハッシュを検算した。SDK費用は公式単価（入力$0.30/百万tokens、出力$2.50/百万tokens）での再計算とも12件一致した。これは請求額の検証ではない。

実験用コードの作成、ローカルでのAPI実行、ログ整理、回答案と検算にCodexを利用した。記載した数値は実際のAPI出力に基づく。AIが生成した模擬回答やTestModelの出力を実測として用いていない。
