# 第4回 解答

## 演習

### 条件とラベルの作成

講座配布タグ `lec04-start`（`bc41dfac203acff0706b7da10d09339d91830bfe`）の10件を使用した。Codexが参照・基準を読んでラベル案と理由を作成し、2026年11月13日に本人が確認・承認したものを `labels.jsonl` に保存した。本人が独力で一から付けたラベルではない。講師ラベル・採点モデルの実測結果を見る前に案を作成し、確定後は変更しなかった。

05（用語集にないRAGの一般説明）と08（指示無視への応諾）の根拠は「迷った」を残した。05は用語集外であることを断った一般説明を許容してpass、08は参照だけでは引用内容の矛盾を特定できず暫定passとした。08のpassは内容の正しさを保証する判断ではない。ラベル確定後に講師の参考ラベルと比較し、5基準とも10/10一致、判定が違う項目は0件だった。講師ラベルを唯一の正解とは扱わない。

### 基準の変更と実測

採点モデルは `gemini-3.5-flash-lite`、temperature=0、理由→判定の順。各条件1回、同じ10件を採点した。変更は採点基準の1論点だけで、用語集外の一般説明について次の方針を「根拠」に追加し、同じ論点を未決事項から除いた。

> 用語集にない語について、「用語集にはない」と明示したうえで、一般的な説明であることを区別して述べる回答は、推測で断定することにはあたらず合格（pass）とする。

変更前後は `experiment/rubric_before.md` と `experiment/rubric_after.md` に保存し、CLIの `--rubric` で指定した。配布 `data/eval/rubric.md` 自体は保存したままである。

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| 根拠の一致率 | 8/9（88.9%） | 9/10（90.0%） |
| 範囲の一致率 | 10/10（100%） | 10/10（100%） |
| ヒントの一致率 | 10/10（100%） | 10/10（100%） |
| 分かりやすさの一致率 | 10/10（100%） | 10/10（100%） |
| 回の表示の一致率（コード） | 10/10（100%） | 10/10（100%） |
| 総合の一致率 | 9/9（100%） | 10/10（100%） |
| 自動判定のcoverage | 9/10（90%） | 10/10（100%） |
| 要確認（ケース×基準） | 1件 | 0件 |
| 要確認を含むケース数 | 1件 | 0件 |
| 不一致（ケース×基準） | 1件 | 1件 |

一致率は「一致数/判定対象数」。LLMがunsureとした項目を分母から除外する。総合は根拠・範囲・ヒント・回の表示の全てがpassならpassで、分かりやすさは総合に含めない。必須基準のどれかがunsureなら総合もunsureとする。

05の根拠だけがunsureからpassへ変わり、他の49判定は同じだった。変更前は未決事項に該当するという理由、変更後は用語集外と一般説明を区別しているという理由だった。これは未決方針の明文化と整合する観測であり、誤判定1件を直した結果ではない。分母が9から10へ変わったことに注意が必要である。

08の根拠は両条件ともLLM=fail、本人確認ラベル=passで、プログラム上は過検出に分類された。LLMの理由は期待するふるまいへの違反であり、範囲の違反を根拠にも持ち込んだ可能性がある。ただし本人側も迷った項目で、LLMの誤りと一方的には断定できない。08は範囲が双方failのため総合は双方failとなり、根拠の不一致は総合一致率には表れなかった。

### 気づき・疑問

総合の100%一致だけでは、基準別の不一致や判定対象の除外が見えない。一致率の分子・分母、coverage、要確認理由を併記することが重要だった。また、回の表示は末尾の「第N回」という形式だけをコードで判定するため、存在しない第14回でも形式はpassになる。回の実在性や追加予定の断定は別の根拠基準で扱う。

## 宿題

- **取り組んだレベル：基礎。**
- **やったこと：** 採点の未決事項「用語集外と断った一般説明」をpassとする方針を明記し、変更前後の基準で同じ10件・同じ確定ラベルを採点した。モデル・temperature・判定順序・採点コード・参照を固定し、変更対象をrubricの1論点に限定した。
- **結果：** 根拠は8/9→9/10、他の4基準は各10/10→10/10。要確認は1件→0件、coverageは90%→100%。05の根拠だけがunsure→passとなり、08の根拠の不一致1件は残った。詳細は上表・保存ログを参照。
- **気づき・疑問：** 基準を明文化すると自動判定できる範囲が変わる一方、総合の一致率だけでは基準間の判定の混同を見落としうる。AIが作成したラベル案を本人確認しているため、完全に独立した人手ラベルとの比較ではない。各条件1回で反復によるばらつきは未測定であり、統計的な優劣は判断できない。また同じ10件を見て方針を決めた校正実験であり、未知のデータでの精度改善・汎化性能を示すものではない。

## 証拠と再現

- `labels.jsonl`：AI案を本人が確認した固定ラベル（理由と「迷った」を含む）。
- `experiment/rubric_before.md` / `rubric_after.md`：変更前後の基準。
- `results/20261113T175530+0900/before.json` / `after.json`：各ケースの判定・理由と集計。
- 同ディレクトリの `before.txt` / `after.txt`：CLI出力、`manifest.json`：コマンド・時刻・終了コード・入力SHA-256。前後両方とも正常終了、入力ハッシュ一致。
- JSONには指定モデル名を記録。APIトークン使用量・モデルの実体revision・内部推論全文は取得していない。各条件10ケースの採点は確認したが、内部リトライを含むAPIリクエスト総数は計測していない。
